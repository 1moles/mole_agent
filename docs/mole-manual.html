mole-agent 0.4.1 · 技术手册

Mole 架构与使用手册

Mole 是运行在终端里的编码助手：在任意项目目录执行 mole，用自然语言让它读代码、改代码、跑命令、做检视。底座是 openJiuwen 的 DeepAgent，Mole 负责人设、工具、安全 rails、模型接入和终端交互。

  • 0.4.1mole-agent
  • ≥0.1.18openjiuwen
  • 3.11–3.13Python
  • 16个工具（Windows 17）
  • 2个子 agent
  • 11个斜杠命令
  • 262个测试

依据：仓库 main 分支 7949fac，加上尚未提交的 Windows 便携包打包脚本（2026-09-24）。数字和默认值均对照源码核实。

01概览

一句话：openJiuwen 提供 agent 的引擎，Mole 把它装配成一个可以放心交给它改代码的终端工具。

SDK 负责
ReAct 循环与外层任务循环、todo 规划、技能加载、子 agent 调度（task_tool）、上下文压缩、检查点、模型客户端、流式输出。
Mole 负责
多供应商模型接入、人设与项目记忆、自定义工具、安全 rails（拦截 / 确认 / 只读）、提问、会话历史与续聊、上下文管理命令、连接诊断、终端交互。

典型用法：

cd ~/code/your-project
mole                                  # 进入对话
mole -p "解释一下这个仓库的结构"       # 单次执行后退出
mole -c                               # 继续这个项目最近的会话

模块职责

一轮对话怎么跑

  1. 读取输入。输入框基于 prompt_toolkit。以 / 开头的走命令注册表：/review 展开成提示词交给 agent，其余命令在本地执行，不经过模型。
  2. 启动运行。Runner.run_agent_streaming(agent, {"query": …}, session=会话 id)。SDK 先从检查点恢复这个会话的状态，所以续聊只需要用回原来的会话 id。
  3. 调模型前。DeepAgent 外层任务循环驱动内层 ReAct。每次调模型前先跑 before_model_call rails，再由 ContextEngine 按占用决定是否压缩，最后组装上下文窗口，以流式请求发给模型。
  4. 调工具。模型要调工具时，before_tool_call rails 按优先级裁决：驳回、中断等你确认或回答、或者放行；执行后 after_tool_call 写终端轨迹和审计日志。
  5. 渲染输出。文本分片、工具调用与结果、压缩事件、上下文占用、中断请求都写进会话输出流，由 StreamRenderer 渲染到终端。
  6. 处理中断。遇到确认或提问，输出流结束，终端收集你的回答，打包成 InteractiveInput 用同一个会话再跑一次，SDK 从中断处继续。
  7. 收尾。SDK 把会话状态（含对话上下文、未完成的中断）存进检查点；Mole 把输入、回复、工具摘要、压缩提示写进会话历史。

Rails

rail 是挂在 agent 生命周期上的钩子对象，priority 数值大的先执行。主 agent 挂载的 rails：

QuestionRailMole90before_tool_call拦下 question 工具：中断等你回答，把答案作为工具结果交回；参数不合法时直接让模型重来
ContextProcessorRailSDK85init把预设的上下文处理器链放进 ReActAgent 配置（转存大段工具输出、按阈值压缩）

子 agent

主 agent 用 task_tool 派活。子 agent 在独立上下文里跑完，只把结论交回，读大量代码不会挤占主对话的上下文。

子 agent什么时候用实现迭代上限
explore_agent只读探索：某个功能在哪、怎么实现、调用关系直接用 SDK 的 build_explore_agent_config，提示词和描述都是 SDK 自带的；Mole 只替换 railsSDK 默认
code_reviewer代码检视、合入前检查、大改动后自查Mole 自己的提示词；有 code-review 技能时严格按技能执行；返回「阻塞 / 建议 / 可选」分级、带 路径:行号 的问题和合入结论40
  1. 主 agent 调用 task_tool(subagent_type="code_reviewer", task_description="检视未提交改动")。
  2. SDK 现场创建子 agent，上下文里只有任务描述；和主 agent 共用沙箱和 token 统计。
  3. 子 agent 读技能 → git_changes → read_file / grep。bash 经过 ReadOnlyShellRail：只读命令放行，其余直接驳回，不弹确认。
  4. 每个工具调用写审计（agent=code_reviewer），并经 ActivityFeed 在终端显示为以 │ 开头的一行。
  5. 报告交回主 agent，由主 agent 转述；需要改代码时由主 agent 来改，照常需要你确认。

每个子 agent 的模型可以在 models.toml 的 [subagents] 里单独指定；没写就跟随主 agent 当前模型（/model 切换后也跟着变）。MOLE_ENABLE_SUBAGENTS=false 整体关闭。

上下文工程

压缩由 SDK 的处理器链完成，每次调模型前依次检查：

处理器什么时候触发做什么调模型
MessageSummaryOffloader单条工具结果超过窗口 10%；空闲 300 秒后占用超过 50% 时，再处理超过 5% 的旧结果全文转存，上下文里只留开头和结尾各约 2000 字的预览；read_file 的结果不处理否
SessionMemoryCompressor预设里是关闭的—
DialogueCompressor占用达到窗口 80%把最新一条用户消息之前的轮次压成摘要是
CurrentRoundCompressor压完仍 ≥ 80%把本轮的工具调用过程压成摘要是
RoundLevelCompressor压完仍 ≥ 80%除最后 4 条消息外全部压成摘要是

另外两条路径：模型报「上下文超长」时，ReActAgent 通过 ContextEngine.recover_from_model_exception 主动压缩一次再重试同一步（流式输出已经开始时不重试）；/compact 走同一个主动压缩入口。压缩后 SDK 会重新注入技能、已读文件、计划和 todo 状态。

Mole 在这之上补了四件事：

  • 只收流式的网关也能压缩。压缩器按配置自己建模型客户端、调非流式 invoke；CompressionRail 在初始化时把这份配置换成 SDK 客户端注册表里登记的 mole_stream_only 客户端。
  • 说清楚为什么没压。SDK 压缩失败只写日志、事件里只有 noop；CompressionWatcher 订阅 LLM_CALL_ERROR，按压缩操作 id 记下原因。
  • 认中文报错。SDK 只认英文的超长报错；Mole 在 recover_from_model_exception 外包一层，把「输入长度超过…上下文」之类换成它认得的说法。
  • 看得见。压缩事件在终端合成一行提示；/context 查看占用，/compact 手动压缩。

去哪里找配置

配置查找顺序（前者优先）

models.toml

models.toml
default = "deepseek/deepseek-flash"

code_reviewer = "deepseek/deepseek-v4-pro"

[providers.deepseek]

[providers.modelarts]                        # 请求头鉴权 + 只收流式的内部服务
client_provider = "ModelArts"
api_base = "https://<在线服务调用地址>/v1"
auth = "headers"
headers = { "X-Auth-Token" = "${MODELARTS_TOKEN}" }
stream_only = true
models = ["<部署的模型名>"]

[providers.internal]                         # 公司内部 OpenAI 兼容网关
client_provider = "OpenAI"
api_base = "https://llm-gateway.example.com/v1"
api_key_env = "INTERNAL_LLM_KEY"
verify_ssl = false                           # 自签证书时
headers = { "X-Tenant" = "my-team" }
models = ["coder-large"]
字段说明
default启动默认模型，写法同 -m
[subagents]子 agent 名 = 模型；供应商没有 key 时回落到主模型，启动时提示
client_provideropenjiuwen 的协议或厂商标识：OpenAI（任何 OpenAI 兼容接口）、Anthropic、DeepSeek、DashScope、Moonshot、Zhipu、SiliconFlow、OpenRouter、ModelArts、VolcEngine、Qianfan、MiniMax 等；写错启动时报出可选值
api_base接口地址，一般写到 /v1
api_key_env存放 key 的环境变量名（推荐）；也可以写 api_key，但不要把密钥写进这个文件
authapi_key（默认）/ headers / none，见下表
headers自定义请求头，值可写 ${变量}；Authorization、Host 等会被 openjiuwen 丢弃，启动时提示
stream_only网关只接受 stream=true 时打开（也接受 stream = true 的写法）。不要自己往请求参数里加 stream，非流式调用会报 'AsyncStream' object has no attribute 'choices'
models常用模型列表，/model 里按序号选；不在列表里的也能用 供应商/模型名 直接指定
temperature max_tokens timeout verify_ssl供应商级覆盖；没写时用全局的 MOLE_* 默认值
auth发送的鉴权信息
api_keyAuthorization: Bearer <key>，headers 作为附加请求头
headers只发 headers（如 ModelArts 的 X-Auth-Token、X-Apig-AppCode）；只配了 headers、没配任何 key 时自动按这种方式
none不鉴权（本地 vLLM、不校验的内部网关）

缺环境变量的供应商不会出现在 /model 的编号里，列表末尾会提示要设置哪个变量。

› /compact 保留登录模块的改动和没做完的待办
⟳ 正在压缩上下文（42 条消息，对话约 21.1k tokens，重点保留：保留登录模块的改动和没做完的待办）… 完成，42 → 6 条消息，对话约 21.1k → 3.4k tokens（省 84%）

对话过程中的自动压缩也会提示一行：

  ⟳ 上下文已压缩：对话约 152.3k → 18.6k tokens（省 88%）
  ⟳ 模型报上下文超长，已压缩上下文：对话约 30.1k → 6.2k tokens（省 79%），重试中
  ⚠ 上下文压缩失败，上下文保持原样：HTTPStatusError: … 400 …（网关只接受流式请求的话，在 models.toml 里给这个供应商加上 stream_only = true）
  • 压缩结果写回检查点，重启后续聊拿到的也是压缩后的上下文；/compact 执行中可以 Ctrl+C 取消，上下文不变。
  • 压缩要调一次模型，超过 1 秒会先显示「正在压缩…」，完成后接在同一行后面。同一个失败原因一轮只提示一次。
  • 压缩用的是启动时的模型，/model 切换后不变；stream_only 也按启动时的供应商。
  • 续聊回来还没发消息时不能 /compact（压缩器要到第一次对话时才装上），先聊一句即可；快满时发消息也会先自动压缩。
  • MOLE_ENABLE_CONTEXT_RAILS=false 关闭压缩，/context 会显示「自动压缩没有开启」。

/review                      # 检视未提交改动
/review 提交 a1b2c3d          # 某个提交
/review 和 main 比            # 当前分支相对 main 的全部改动
/review mole_agent/cli.py    # 指定文件，按整份代码检视
  • 有 code_reviewer 子 agent 时，/review 让主 agent 通过 task_tool 交给它，读 diff 和上下文不占主对话；报告原样转述给你，不改任何文件。
  • 项目里有 code-review 技能时按技能执行。Mole 仓库自带 .mole/skills/code-review/：SKILL.md 定流程和输出格式，references 里是本项目约定和细项清单。
  • 结果按「阻塞 / 建议 / 可选」分级，每条带 路径:行号、影响和修改建议，最后给出合入结论。
  • 也可以直接说「检视一下我的改动」。

4.9扩展 Mole

加一个工具

复制 mole_agent/tools/_template.py 为 <工具名>.py（文件名与工具名一致），实现 create(settings) -> Tool，重启即可，不用改其他文件。

  • 需要按配置开关时加 enabled(settings) -> bool。
  • 不写文件、不改状态的工具加 READ_ONLY = True，只读子 agent 才会拿到它。
  • description 写清「做什么、什么时候该用」；参数写成 JSON Schema，给默认值和说明。
  • 阻塞 IO 放进 asyncio.to_thread，子进程带 timeout；路径经过 resolve_inside 限制在项目内；输出用 truncate 截断。
  • 缺 create、工具名重复、create 报错时，启动直接报出是哪个文件。

加一个子 agent

在 mole_agent/subagents/ 新建 <子agent名>.py，实现 create(env: SubagentEnv) -> SubAgentConfig：rails 用 env.read_only_rails(名字)，工具用 env.tools()，模型用 env.model_for(名字)，再传 workspace=env.workspace(名字) 和 sys_operation=env.sys_operation。agent_card.description 写清什么时候派给它、task_description 写什么。参考 code_reviewer.py。

子 agent 必须只读。task_tool 在内部运行子 agent，子 agent 触发的确认和提问传不到终端（openjiuwen 0.1.18）。不要给它挂 ApprovalRail、QuestionRail 或写文件工具。

加一个 rail

在 rails.py 继承 AgentRail，覆写需要的钩子（before_model_call、after_tool_call 等），显式设 priority 并注释为什么排在谁前后，然后挂进 agent.py 的 rails 列表。要拦截并裁决工具调用就继承 BaseInterruptRail，在 resolve_interrupt 里返回 approve()、reject(...) 或 interrupt(...)。

加一个斜杠命令

在 mole_agent/commands/__init__.py 的 default_registry() 里注册 CommandSpec：名称、说明、异步处理函数，按需加用法、别名、示例、参数补全、可用性判断。菜单、帮助、分发自动读取；需要运行时能力时在 cli.py 的 Repl.command_context() 接入。设计取舍见仓库里的 docs/slash-command-architecture.md。

加技能

SKILL.md 放到 <项目>/.mole/skills/<名字>/（只在该项目生效）或 ~/.mole-agent/skills/<名字>/（所有项目共用），格式与 Claude Code skills 一致，也可以软链接 ~/.claude/skills 里的技能。技能目录会自动加入文件沙箱，references/、scripts/ 都能读到。新增、修改技能不用重启（会话中途新增的 /new 后生效）；启动后新建的软链接要重启才加入沙箱。示例见 examples/skills/commit-message/。

接 MCP 服务

.mcp.json
{"mcpServers": {
  "fs":     {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]},
  "remote": {"type": "http", "url": "http://mcp.internal/mcp", "headers": {"Authorization": "Bearer xxx"}}
}}

放在项目根目录（优先）或 ~/.mole-agent/mcp.json。支持 stdio、sse、http / streamable-http；"disabled": true 跳过某个服务。

项目约定

在项目根目录写 MOLE.md（也兼容 AGENTS.md、CLAUDE.md、OPENJIUWEN.md），启动时注入系统提示词，最多 2 万字。

4.10连不上模型

先跑 mole --check。前几行说明实际用的是哪个供应商、哪种鉴权、是否只走流式、哪份 models.toml；调用失败时打出异常链（最后一行是根因），连接类错误还会按 openjiuwen 的实际行为逐步检查，把这段输出发给维护者即可。

诊断里的 ✗原因与处理
会走代理 / 连接代理失败 / CONNECT 403、502终端里设了 http_proxy 等代理变量，内网地址也发给了代理。把域名加进 NO_PROXY，要带前导点：.inner.example.com
NO_PROXY 写法openjiuwen 比 curl 严：example.com 不包含子域名，*.example.com 不支持；它还优先用 http_proxy（即使地址是 https）。httpx 另外会读 ALL_PROXY
DNS 解析失败 / TCP 超时不在内网、没连 VPN，或所在网络到不了这个地址
证书校验失败服务用公司内部 CA 的证书而本机 Python 不信任它。python.org 安装的 Python 先运行「Install Certificates.command」；可把内部根证书加入信任库，或在供应商下临时写 verify_ssl = false
TLS 协商失败openjiuwen 只允许 TLS1.2+，TLS1.2 下只允许 ECDHE + AES-GCM 套件；诊断会对比 Python 默认配置能否握手
'AsyncStream' object has no attribute 'choices'往请求参数里加了 stream=True。去掉它，改在供应商下写 stream_only = true
400，提示只支持流式网关只收流式请求：供应商下加 stream_only = true

注意 ~/.mole-agent/models.toml 优先于仓库里的，~/.mole-agent/state.json 会记住上次 /model 选的模型。

05安全模型

几道防线互相独立：拦截不依赖你的确认，确认不依赖模型自觉，沙箱不依赖前两者。

层机制配置
文件沙箱文件工具和命令里引用的路径只能落在项目目录、agent 工作区、技能目录（含软链接指向的目录）MOLE_RESTRICT_TO_PROJECT
命令拦截CommandGuardRail 对 bash 和 powershell 执行拒绝规则，命中直接驳回；命令先按 | && || ;、单个 & 和换行切成子命令再逐段检查MOLE_EXTRA_BASH_DENY
人工确认ApprovalRail：写文件、改文件、执行命令前询问；bash 和 powershell 算一组MOLE_CONFIRM_TOOLS，-y 关闭
子 agent 只读没有写文件工具和 question；bash 经 ReadOnlyShellRail 只放行白名单命令，powershell 一律拒绝；不挂人工确认rails.read_only_violation
审计每次工具调用一行 JSONL：时间、项目、agent、工具、参数、是否成功、裁决（executed / rejected_by_guard / rejected_by_user）、耗时、结果前 500 字MOLE_AUDIT_LOG
密钥key 和 token 只来自环境变量或 .env（已被 git 忽略）；--check 只显示请求头名字api_key_env、${变量}

子 agent 的只读 shell

  • 放行的命令：ls cat head tail wc grep egrep fgrep rg find pwd echo file stat du sort cut diff which basename dirname，以及 Windows 的 dir type tree where findstr。
  • git 只放行只读子命令：status diff log show blame grep ls-files ls-tree rev-parse describe shortlog cat-file merge-base rev-list branch。
  • 白名单命令里能写文件或执行程序的参数单独拦掉：find -delete / -exec、sort -o、rg --pre 等；输出重定向、命令替换、单个 &、设置环境变量也会被拒。

07已知限制

限制影响与应对
压缩固定用启动时的模型/model 切换后仍用启动时的模型和网关做压缩；stream_only 也按启动时的供应商判断
内部模型的窗口按 200k 算模型名不在 SDK 内置表里时用默认值；实际窗口更小时要等接口报超长才压缩（会压缩后重试一次）
超长只重试一次压缩后仍放不下会报错，提示用 /compact 或 /new；流式输出已经开始时不重试
续聊后首条消息前不能 /compactrails 要到第一次对话才初始化；先聊一句即可
子 agent 不能确认和提问task_tool 内部的中断传不到终端（openjiuwen 0.1.18），所以子 agent 只读，范围不明确时写明假设
旧会话不能续聊开启续聊之前的会话只有历史、没有检查点
会话参数没有补全/history、/resume 的序号或 id 要手动输入
NO_PROXY 规则严格openjiuwen 不支持通配符、不含子域名，要写成 .example.com
SDK 打包缺陷openjiuwen 0.1.18.x 会无条件导入 opentelemetry-sdk，Mole 显式依赖它
