# 检视细项清单

按需逐项过，不必每项都写进报告；只报告真正发现的问题。

## 正确性
- [ ] 边界输入：空字符串、`None`、空列表、超长内容、非 UTF-8 内容、Windows 路径
- [ ] 失败路径：异常是否被正确处理或向上抛出；错误信息是否能帮用户定位问题
- [ ] 宽泛的 `except Exception` 是否吞掉了本该暴露的错误（允许的地方要有注释说明）
- [ ] async：漏写 `await`；在协程里做阻塞 IO / `time.sleep`；`CancelledError` 被吞掉；
      后台 task 没人等待或没处理异常
- [ ] 资源：文件、子进程、网络连接用 `with` / `async with` 释放；子进程有超时
- [ ] 可变默认参数（`def f(x=[])`、dataclass 字段未用 `default_factory`）
- [ ] 共享状态：全局变量、类属性、`Runner.resource_mgr` 这类进程级单例是否被意外共享或污染
- [ ] 字符串处理：编码显式写 `encoding="utf-8"`；正则是否转义、是否有灾难性回溯
- [ ] 与已有行为的一致性：同类功能是否复用了已有函数，而不是另写一套

## 安全
- [ ] 命令拼接：有没有把用户或模型给的内容拼进 shell 命令（`shell=True`、`os.system`）
- [ ] 路径：`..`、绝对路径、符号链接能否绕过项目目录限制
- [ ] 敏感信息：key、token、内部地址是否进入日志、审计、异常信息、提示词或 git 仓库
- [ ] 反序列化：`pickle`、`yaml.load`（应为 `safe_load`）、`eval` / `exec`
- [ ] 默认值：是否关闭了 SSL 校验、放宽了沙箱、减少了需要确认的工具

## 兼容性
- [ ] 公开函数 / 类的签名、返回值、异常类型是否变化，调用方是否都已更新
- [ ] 配置文件、状态文件格式变化后，旧文件还能不能读
- [ ] 依赖版本范围是否合理；有没有用到只在新版本才有的 API
- [ ] 跨平台：路径分隔符、信号处理（Windows 没有 `add_signal_handler`）、换行符

## 测试
- [ ] 正常、异常、边界三类用例是否都有
- [ ] 测试是否依赖外部网络、本机配置、执行顺序或当前时间
- [ ] 断言是否足够具体（避免只断言「没报错」）
- [ ] 修复的 bug 是否有能复现它的回归测试

## 可维护性
- [ ] 函数是否过长、职责是否单一；命名是否表达意图
- [ ] 重复代码、死代码、调试残留（`print`、注释掉的代码、`TODO` 没有说明）
- [ ] 魔法数字、硬编码路径是否提取为常量或配置
- [ ] 注释是否与代码一致

## 性能
- [ ] 循环里的文件 / 网络 / 子进程调用
- [ ] 一次性读入可能很大的文件或命令输出，没有上限
- [ ] 缓存、列表、历史记录是否会无界增长

## AI 生成代码的常见问题
- [ ] 调用了不存在的函数、参数或配置项（去 SDK 源码或文档里确认）
- [ ] 为「兼容」写了永远走不到的分支，或重复的防御性检查
- [ ] 没按项目约定写，而是另起一套风格或工具函数
- [ ] 测试只验证了 mock 本身，没有验证真实行为
- [ ] 注释或文档描述的行为与代码实际行为不一致
